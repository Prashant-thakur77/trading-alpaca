# Safe-default report — submitting requires explicit `--live`

## The incident (recap)

2026-08-29 14:43:11 UTC: backticks inside an unrelated `git commit -m`
message were shell-expanded and executed `make session`, which — under the
old submit-by-default behaviour — sent a real (unfilled, then cancelled)
multi-leg paper order to Alpaca. Every safety component behaved correctly
(guard ALLOW, cancellation worked, journal stayed intact); the gap was that
`scripts/run_session.py` submitted unless `--dry-run` was explicitly passed,
so an accidental invocation of the shortest, most typo-prone command could
reach the broker.

## What changed

### `scripts/run_session.py`
- Added `--live` (`store_true`, default `False`). It is now the **only** way
  to reach the broker.
- `--dry-run` is kept as an explicit no-op alias (unchanged flag), but the
  gating logic no longer keys off `args.dry_run` directly. A single
  `live = args.live and not args.dry_run` is computed once, right after
  argument parsing, and is the sole source of truth for "will this cycle
  reach the broker." Every place that used to branch on `args.dry_run` (the
  open-book management gate, the committee's journal argument, all five
  `_abstain(..., dry_run=...)` call sites, and the final
  payload/no-submission block) now branches on `not live` instead. This means
  passing no flags behaves **exactly** like `--dry-run` did before, including
  in edge cases like a guard refusal (previously reachable only on the
  submit-by-default path) — with no flags, the pipeline now takes the same
  "stop before submission" branch there too.
- `--live --dry-run` together resolves to `live = False` — fails closed on
  the ambiguous combination rather than picking a side.
- A mode banner prints immediately after argument parsing, before the kill
  switch or any broker/data call, so it appears on every run regardless of
  how far the cycle gets:
  - not live: `MODE: not live — no order will be sent to the broker this run
    (pass --live to submit).`
  - live: `MODE: LIVE — orders WILL be sent to the broker this run.`
- The kill switch check is untouched and still runs first, so `--live` can
  never bypass it.

### `Makefile`
- `make session` (the exact command the incident accidentally triggered) now
  runs `run_session.py` with **no flags** — the safe, non-submitting default.
  It stays the shortest, most likely command and is now permanently
  incapable of submitting, regardless of how it gets invoked.
- Added `make session-live` → `run_session.py --live`, the explicit,
  intentional live path.
- `make session-dry` is unchanged (`--dry-run`), kept for existing muscle
  memory/docs.
- Help text and `.PHONY` updated accordingly.

### `README.md`
- Safety section: added rule 8, "Submitting requires an explicit `--live`
  flag," documenting the mechanism, the `make session` / `make session-live`
  split, and the incident itself (what happened, why it was harmless, and
  why the design changed) — not hidden.

### `judge/scenarios/fail_closed.json`
- Its `recorded_outcome.stdout` is asserted byte-for-byte against a real,
  unedited re-run of `run_session.main` (per its own `provenance` field), so
  it had to be regenerated to include the new mode banner and the
  now-default "open book is not managed" line. Regenerated by actually
  invoking `run_session.main` with the fixture's injected failure and
  capturing the real output (not hand-edited).

## TDD evidence

Added `TestSubmitRequiresLive` to `tests/test_run_session_main.py` (8 tests)
covering every case in the task's test list, plus the fail-closed/malformed
case:
- `test_no_flags_submits_nothing` — reproduces the incident shape exactly
  (`main()` with no flags), asserts the injected CLI's `post_order` is never
  called (`cli.posted == []`).
- `test_live_with_a_guard_approved_candidate_submits` — `--live` + a
  guard-approved candidate submits.
- `test_dry_run_flag_still_submits_nothing`.
- `test_live_combined_with_dry_run_still_submits_nothing` — ambiguous
  combination fails closed.
- `test_live_does_not_override_the_kill_switch`.
- `test_mode_banner_says_no_order_will_be_sent_without_live` /
  `test_mode_banner_says_orders_will_be_sent_with_live`.
- `test_malformed_flags_fail_closed` — an unrecognized flag exits via
  argparse (`SystemExit`) with nothing posted.

Written first and run to confirm **red** against the unmodified code: 6 of 8
failed as expected — `test_no_flags_submits_nothing` failed because
`post_order` *was* called (the exact incident), and the `--live`/banner tests
failed with `SystemExit: 2` (`--live` unrecognized). After implementing the
flag inversion, gating, and banner, all 8 went green, and the rest of the
suite was fixed to match (see below) — full run: `700 passed`.

## Every existing test updated, and why

`scripts/run_session.py` is the only production caller of
`OptionsExecutor.submit()`, and the money path is exercised by dozens of
`tests/test_run_session_main.py` tests that call `main()` through the `bench`
/ `llm_bench` fixtures. Any test that depended on the **old** submit-by-default
behavior — i.e. asserted `cli.posted` was non-empty, or asserted a journal
entry / open-book write that only happens on the submission path — now needs
`--live` explicitly, since it is testing genuine submission behavior, not a
default. No assertion was weakened; only argv changed. 18 tests, all in
`tests/test_run_session_main.py`:

| Test | Why it needs `--live` |
|---|---|
| `TestWorkingOrders::test_a_working_order_in_another_underlying_does_not_block` | asserts `len(cli.posted) == 1` — genuinely testing that an order reaches the broker when it should |
| `TestWorkingOrders::test_the_submitted_payload_is_idempotent_at_the_broker` | asserts `cli.posted[0]["client_order_id"]` — needs a real posted payload |
| `TestPortfolioStateIsDerived::test_a_win_resets_the_losing_streak` | asserts `len(cli.posted) == 1` |
| `TestPortfolioStateIsDerived::test_yesterdays_fill_does_not_count_against_today` | asserts `len(cli.posted) == 1` |
| `TestGuardRefusalShortCircuits::test_a_guard_refusal_never_reaches_executor_submit` | the TOCTOU assertion (`executor.submit` monkeypatched to raise, proven unreached) and the printed "guard refuses" text only occur on the branch reached after a live pre-check refusal; without `--live` the cycle now takes the dry-run branch and never reaches that code at all, so the test would pass vacuously and stop proving anything |
| `TestCommitteeIsWired::test_the_committees_choice_is_the_order_that_is_sent` | asserts the committee's chosen legs are the ones actually posted — needs a real submission |
| `TestCommitteeIsWired::test_the_deterministic_and_committee_paths_can_disagree` | asserts `len(cli.posted) == 1` |
| `TestCommitteeIsWired::test_a_committee_choice_the_guard_denies_is_never_sent` | same "guard refuses" text/branch reasoning as above |
| `TestCommitteeAbstention::test_an_abstention_is_journalled` | the abstain journal write is itself gated by `not live` (a rehearsal, dry or default, stays out of the judged journal — same rule that already applied to `--dry-run`); the test needs a real run to see the write |
| `TestNoLLMFallback::test_no_llm_never_calls_the_committee` | asserts `len(cli.posted) == 1` |
| `TestPremortemRunsBeforeTheOrder::test_a_live_cycle_journals_the_premortem_triggers` | premortem is journalled only just before `executor.submit()`, on the live path |
| `TestPremortemRunsBeforeTheOrder::test_the_premortem_runs_before_anything_is_sent` | checks ordering of `premortem` vs `proposal` journal entries — both only written on submission |
| `TestPremortemRunsBeforeTheOrder::test_a_raising_premortem_still_protects_and_still_trades` | asserts `cli.posted` is non-empty |
| `TestTheOpenBookIsRemembered::test_a_filled_trade_is_written_to_the_open_book` | the open-trade store is only written after a real fill |
| `TestTheNextCycleManagesTheBook::_open_a_position` (shared helper, used by 5 tests in this class) | opening the position that later tests manage/close requires a real submission |
| `TestTheNextCycleManagesTheBook::test_the_next_cycle_closes_a_position_at_the_profit_target` | the *second* call also needs `--live`: `manage_open_book()` — which can submit a closing order — is itself gated by `not live`, matching "anything that moves money is opt-in," so closing a position under test needs `--live` too |
| `TestTheNextCycleManagesTheBook::test_a_closed_position_makes_the_calibration_loop_resolvable` | both calls (open, then close) need `--live` for the same reasons above |
| `TestTheNextCycleManagesTheBook::test_a_position_gone_from_the_book_leaves_the_open_book` | second call needs `--live` so `manage_open_book()` actually runs and clears the store |
| `TestPremortemRunsBeforeTheOrder::test_an_unreadable_open_book_does_not_stop_the_cycle` (`TestTheOpenBookIsRemembered` block) | without `--live`, `manage_open_book()` — and therefore the corrupted-store read this test exists to exercise — is never invoked at all, making the assertion vacuous |

Two closely related tests were **not** changed because they already exercise
the `--live`-independent parts of the pipeline and their assertions still
hold true either way:
- `TestGuardRefusalShortCircuits`-adjacent guard-deny tests that only assert
  `cli.posted == []` and check the guard's *reason* text (printed
  unconditionally, before the live/not-live gate) — e.g.
  `test_daily_loss_halt_actually_fires`, `test_consecutive_losses_from_the_journal_reach_the_guard`,
  `test_one_new_trade_per_underlying_per_day_actually_fires`,
  `test_the_existing_books_greeks_are_charged_against_the_limit`,
  `test_three_spreads_fill_the_position_cap`. These pass under both old and
  new semantics without modification since `guard.evaluate()` and its print
  line run unconditionally, before the submission gate.
- `TestCommitteeIsWired::test_the_committee_is_called_by_default`,
  `test_the_committee_receives_the_built_candidates_and_live_state`,
  `test_the_guard_still_runs_on_whatever_the_committee_chose`, and all of
  `TestCommitteeAbstention` except `test_an_abstention_is_journalled` — the
  committee runs and abstentions are decided during the selection phase,
  which happens unconditionally, before the live/not-live gate. No `--live`
  needed.

No existing assertion was weakened, loosened, or deleted — only `argv` was
extended to make the tests' true intent (submission, a real closing order, a
journalled abstention) explicit rather than implicit in a default.

## Also fixed to stay green

`judge/scenarios/fail_closed.json`'s `recorded_outcome.stdout` is compared
byte-for-byte by `scripts/replay.py` against a real, unedited run of
`run_session.main`. Its provenance field says exactly that ("The stdout and
exit code recorded below are the real, unedited output of that call"), so it
was regenerated by actually re-running that call (not hand-edited) to include
the new mode banner and the now-default "the open book is not managed" line.
The exit code (`1`, fail-closed on the data outage) is unchanged.
